# Security

## Review checklist

| Check | How it is enforced |
|-------|-------------------|
| Hostname set | Vagrant + [`provisioning/hosts.sh`](../provisioning/hosts.sh) |
| Static IP | Vagrant private_network ([`infrastructure/network.yml`](../infrastructure/network.yml)) |
| `devops` exists | [`provisioning/users.sh`](../provisioning/users.sh) |
| `devops` in `sudo` | `users.sh` (password required — no NOPASSWD) |
| Root SSH disabled | `PermitRootLogin no` |
| Password auth disabled | `PasswordAuthentication no` |
| Key-only login | Project key → `~devops/.ssh/authorized_keys` |
| AllowUsers | `devops` globally; `vagrant` only via NAT `Match` |
| UFW active + SSH allowed | [`provisioning/firewall.sh`](../provisioning/firewall.sh) + [`config/ufw.rules`](../config/ufw.rules) |
| Secure umask | `umask 027` via [`config/`](../config/) templates |
| Automatic updates | `unattended-upgrades` + [`config/20auto-upgrades`](../config/20auto-upgrades) |

Run all of the above automatically:

```bash
make verify
make review
```

Test scripts: [`tests/`](../tests/) (e.g. `check_umask.sh`, `check_updates.sh`, `check_ssh.sh`).

## SSH

Template: [`config/sshd_config`](../config/sshd_config) → `/etc/ssh/sshd_config.d/99-automation-alchemy.conf`  
Applied by: [`provisioning/ssh.sh`](../provisioning/ssh.sh)

Notable settings:

- `PermitRootLogin no`
- `PasswordAuthentication no`
- `PubkeyAuthentication yes`
- `AllowUsers devops` — review access over the private network
- `Match Address 10.0.2.0/24` → also allow `vagrant` so `vagrant ssh` still works on NAT

Project key (gitignored):

```text
keys/id_ed25519
keys/id_ed25519.pub
```

Generated by `make create` if missing.

Manual checks:

```bash
ssh -i keys/id_ed25519 devops@10.10.0.10
# Expect: no password prompt for SSH

ssh -i keys/id_ed25519 root@10.10.0.10
# Expect: Permission denied (publickey)
# Note: a host-key prompt is NOT a successful login — auth still fails after yes
```

## sudo

`devops` is in the `sudo` group and **must enter a password**. There is no `/etc/sudoers.d/devops` NOPASSWD drop-in.

Lab password (interactive sudo only): `devops`

```bash
ssh -i keys/id_ed25519 devops@10.10.0.10
sudo -n true    # Expect: failure (password required)
sudo whoami     # Expect: password prompt, then root
```

## Firewall

Base rules ([`config/ufw.rules`](../config/ufw.rules)):

```text
22/tcp
```

Role overlays (applied after the base list):

| Host | Extra allows |
|------|--------------|
| loadbalancer | `80/tcp` (only host with HTTP open to anywhere) |
| web1 / web2 | `80/tcp` from `10.10.0.0/24` |
| appserver | `3000/tcp` from `10.10.0.0/24` |
| backup | no public HTTP (SSH via base rules) |
| cicd | `8080/tcp` and `5000/tcp` from `10.10.0.0/24` only |

```bash
sudo ufw status verbose
# Expect: active; default deny incoming; 22/tcp ALLOW
# On loadbalancer also: 80/tcp ALLOW Anywhere
# On web*/appserver/cicd: those ports only from 10.10.0.0/24
```

## Secure umask (022 / 027 / 077)

**Requirement:** Show umask configuration and demonstrate it in use.

This lab sets umask **`027`** (`0027`) for all users via:

| File | Role |
|------|------|
| [`config/zz-secure-umask.sh`](../config/zz-secure-umask.sh) | Profile snippet → `/etc/profile.d/zz-secure-umask.sh` |
| [`config/login.defs.umask`](../config/login.defs.umask) | `UMASK` in `/etc/login.defs` |
| [`provisioning/umask.sh`](../provisioning/umask.sh) | Installs the templates |
| [`tests/check_umask.sh`](../tests/check_umask.sh) | Automated check |

Demo (as `devops` on any VM):

```bash
# 1) Show current umask (login shell)
bash -lc 'umask'
# Expect: 0027

# 2) Show config files
cat /etc/profile.d/zz-secure-umask.sh
grep -E '^UMASK' /etc/login.defs

# 3) Demonstrate in use
touch /tmp/umask-demo && ls -l /tmp/umask-demo
rm /tmp/umask-demo
# Expect: -rw-r----- (640) — no world access, no group-write
```

| umask | Typical new file | Notes |
|-------|------------------|-------|
| `022` | `644` | Common default |
| `027` | `640` | **This project** |
| `077` | `600` | Owner-only |

## Automatic security updates

**Requirement:** Demonstrate and explain the auto-update configuration.

| File | Role |
|------|------|
| [`config/20auto-upgrades`](../config/20auto-upgrades) | Periodic apt settings |
| [`provisioning/updates.sh`](../provisioning/updates.sh) | Installs + enables `unattended-upgrades` |
| [`tests/check_updates.sh`](../tests/check_updates.sh) | Automated check |

Demo:

```bash
cat /etc/apt/apt.conf.d/20auto-upgrades
```

```text
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
APT::Periodic::Download-Upgradeable-Packages "1";
APT::Periodic::AutocleanInterval "7";
```

```bash
systemctl is-enabled unattended-upgrades
# Expect: enabled

dpkg -l unattended-upgrades | tail -1
# Expect: package installed (ii …)
```

Explain:

| Setting | Meaning |
|---------|---------|
| `Update-Package-Lists "1"` | Refresh apt lists daily |
| `Unattended-Upgrade "1"` | Apply security updates automatically |
| `Download-Upgradeable-Packages "1"` | Prefetch upgradeable packages |
| `AutocleanInterval "7"` | Clean old packages weekly |

Optional:

```bash
grep -E 'Origins|Allowed' /etc/apt/apt.conf.d/50unattended-upgrades | head -20
sudo tail -20 /var/log/unattended-upgrades/unattended-upgrades.log
```

### Extra — IPS (Fail2Ban)

**Requirement:** Explain configuration and demonstrate usage.

| File | Role |
|------|------|
| [`security/fail2ban.sh`](../security/fail2ban.sh) | Install Fail2Ban + sshd jail |
| [`scripts/stretch-ips.sh`](../scripts/stretch-ips.sh) | Runs the script on every VM |

Jail written to `/etc/fail2ban/jail.d/sshd.local`:

```text
[sshd]
enabled = true
port = ssh
filter = sshd
logpath = /var/log/auth.log
backend = systemd
maxretry = 5
findtime = 10m
bantime = 1h
```

Demo:

```bash
cd infrastructure
vagrant ssh loadbalancer -c 'sudo fail2ban-client status'
vagrant ssh loadbalancer -c 'sudo fail2ban-client status sshd'
vagrant ssh loadbalancer -c 'sudo cat /etc/fail2ban/jail.d/sshd.local'
```

| Setting | Meaning |
|---------|---------|
| `maxretry = 5` | Ban after 5 failed SSH attempts |
| `findtime = 10m` | Window for counting failures |
| `bantime = 1h` | How long the IP stays banned |

Optional live demo: fail SSH with a bad user/password several times, then re-check `fail2ban-client status sshd` for a banned IP.

**Requirement:** Explain configuration and demonstrate usage.

| [`monitoring/netdata.sh`](../monitoring/netdata.sh) | Install Netdata; optional UFW for lab CIDR |

Demo:

```bash
# From VirtualBox host:
curl -I http://10.10.0.10:19999
# browser: http://10.10.0.10:19999  (also .11 .12 .20 .30)

# On a guest:
systemctl is-active netdata
sudo ufw status | grep 19999
```

Laptop tunnel example:

```bash
ssh -L 19999:10.10.0.10:19999 -p 2222 USER@HOST
# browser → http://localhost:19999
```
